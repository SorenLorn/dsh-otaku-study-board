## 3. 本轮发现并修正的问题（静态）

| # | 问题 | 根因 | 修正 |
| --- | --- | --- | --- |
| 1 | V4 页面左右内边距变成 **58px**（30+24+4），内容比 V3 窄一圈 | `.osb-page` 已有 padding，`.v4-page` 又加 `s5` | 移除 `.v4-page` 的 padding，只保留背景与圆角 |
| 2 | 卡片内确认弹窗可能被通知/冲突条压住 | `.v4-page>*{z-index:1}` 给每个直接子节点建了层叠上下文，卡片里的 `z-index:60` 被限制在 1 层，而浮层容器是 30 | 背景层改 `z-index:-1`，删除子节点 z-index，弹窗回到根层叠上下文（60 > 30） |
| 3 | 深色模式下 ViewTabs 仍是白底黑字 | 组件里写死了 `#fdfbfb / #2c2630` | 改用 `var(--v4-*, 浅色兜底)`；经典模式没有 v4 token 时仍走原来的浅色值 |
| 4 | 720 下 V4 再压一次 padding，和 V3 不一致 | 4A 的 720 规则 | 删除 padding 覆盖，只保留长描述 `overflow-wrap:anywhere` 防溢出 |

改动文件：`src/client/style/board.css`、`src/client/v4/ui.tsx`、`scripts/ui/components.test.tsx`（新增 C22）。

## 7. 滚动与层级

- 背景 `z-index:-1` + 根 `isolation:isolate`：背景在内容之下、页面背景之上；
- 移除了子节点 z-index 后，卡片内弹窗（60）高于通知/冲突容器（30）；
- 背景 `pointer-events:none`，不拦截点击；
- `position:absolute` 不产生额外滚动；
- **以上均为静态推断，宿主未验证**。

## 9. 剩余问题

**已确认修复（代码层）**：双重内边距、层叠上下文困住弹窗、深色 Tab 写死颜色、720 重复压 padding。

**未验证（必须宿主确认）**：
1. V3 七项回归；
2. V4 页面统一性、玻璃通透度、深色模式；
3. 1440 / 1180 / 1100 / 720 布局与 `scrollWidth`；
4. Hero/ProjectBar 在 V4 下的实际观感（只改了背景/边框/标题色）；
5. 弹窗是否真的盖住通知条、冲突条位置；
6. 背景 blur 的帧率。

**风险**：深色 token 依赖 `html[data-theme="dark"]`，宿主若用其它属性，深色模式不会生效——这不是 CSS 能猜的，需要你切一次深色看。

**视觉建议（未实施，属 4B）**：L1 透明度可在真机上微调；Hero 与 Dashboard 的间距需按截图再收；统计卡微可视化未统一。
